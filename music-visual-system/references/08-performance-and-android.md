# 08 · 性能预算与安卓踩坑总表

这一页的 GPU 预算是全站最紧的：几十张**同时开着 `backdrop-filter`** 的卡片，
外加一个每帧改变它们 3D 变换的 rAF 循环。任何新效果进来之前，先读这一册。

---

## 1. 先测量，再动手

`/music?perf` 挂出 `PerfHUD`（`_components/PerfHUD.tsx`），每 500ms 刷新一次：

```
58 fps · avg 17.1ms · max 42ms · 掉帧 3%
```

| 字段 | 含义 |
| --- | --- |
| `fps` | 实际渲染帧率（高刷屏会显示 90/120） |
| `avg` | 窗口内平均帧时 |
| `max` | 窗口内最差单帧 —— **卡顿尖刺看这个**，平均值会骗人 |
| `掉帧` | 帧时 > 33.4ms（60Hz 下连丢 2 帧以上）的比例 |

- 不带 `?perf` 时组件 mount 后直接返回 `null`、不跑任何循环，**零成本**。
- 开启时也只在 rAF 里做几次加法，每 500ms 写一次 `textContent`（不走 React state）。
- 标签页切走再回来时 rAF 会停摆，`dt > 1000ms` 的那一帧被丢弃并重开统计窗口。
- 真机用法：安卓 Chrome 直接访问 `/music?perf`；App 内配合 `chrome://inspect`。

> 这个 HUD 存在的原因写在它的注释里：**没有低配安卓测试机，卡顿优化必须先有客观
> 数字、不能盲改**。改性能相关的东西，请附上改前改后的数字。

桌面上验证降级路径：**`/music?force=mobile`** 强制 lite 档。

## 2. 每帧成本排序（从贵到便宜）

1. **全屏 `filter: blur()` + 持续 transform**（曾经的 `CoverBackdrop` Ken Burns）——
   弱 GPU 上持续变换会每帧让 blur 缓存失效，逼合成器不断重新光栅化一张全屏模糊位图。
   **这是本页历史上最大的单笔开销**，`lite` 档整条跳过。
2. **每卡 `backdrop-filter`**：拖动时每帧逐卡重新采样 + 模糊背景。这是已知且被接受的
   成本（玻璃是这一页的身份），只能降半径（`blur(18) → blur(6)`），
   最后一张牌是彻底换纯色底。
3. **卡片自身的 `filter`**：曾用于鱼眼景深，**已彻底移除** —— 既是性能问题，
   更是正确性问题（会废掉自己的 `backdrop-filter`）。
4. **大投影的过绘**：墙在拖动时投影区被反复重画，模糊半径越大越贵。安卓专门换了
   一档更小的（`0 18px 44px -16px` → `0 8px 22px -10px`）。
5. **逐帧 DOM 样式写入**：几十张卡 × 每帧 3~5 条属性。靠脏检查与静止停渲压掉。
6. **React 重渲染**：高频 context 接到卡片上是最容易犯、后果最重的错（见 `01`）。

## 3. 三道省算闸（都在 `MusicCanvas` 的 rAF 里）

| 闸 | 条件 | 省掉什么 |
| --- | --- | --- |
| 不重算可见集 | `pan` 位移 ≤ 0.01px | 每帧的数组分配 + 签名字符串拼接 |
| 静止停渲 | pan 没动 且 可见集没变 且 遮挡/隐藏态没翻转 | 整段逐卡循环（每秒上千次 `fisheye` 空算） |
| 样式脏检查 | 新值 === 上一帧值 | 该条属性的 DOM 写入与样式失效 |

另外 `computeInstances` 的 `margin` 从 280 降到 80，是本页**单笔收益最大**的改动
（详见 `02` 第 3 节）。

## 4. 门控矩阵

| 设备 | `lite` | 鱼眼 3D | 卡片玻璃 | 指针视差 / 颗粒 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 桌面（鼠标） | 否 | ✅ | `blur(18)` | ✅ | 满效果 |
| iPad / iPad Pro | 否 | ✅ | `blur(18)` | ✅ | **刻意豁免尺寸规则**：Apple GPU + Metal 扛得住 |
| 安卓手机 | 是 | ✅ | `blur(6)` | ❌ | 规则 1（coarse + ≤1024px） |
| 安卓平板（含 12"+） | 是 | ✅ | `blur(6)` | ❌ | 规则 2：安卓平板 GPU 远弱于 iPad Pro，不给尺寸豁免 |
| `prefers-reduced-motion` | 是 | ✅ | `blur(6)` | ❌ | 鱼眼是页面身份，不因降动效取消 |

**安卓额外的两条**（与 `lite` 正交，靠 `useIsAndroid` / `useIsAndroidApp`）：
弹层打开时整层卡片隐藏、安卓 App 播放时遮挡底部播放器区的卡片（见 `02` 第 7 节）。

**哪些组件根本不降级**（有意为之，别以为是漏了）：
`VolumeControl` 弹层、`PlayModeMenu`、`GlobalVolumeHud` 三个小件全平台恒开毛玻璃 ——
面积小、生命周期短、不做 `filter` 动画，安卓上不构成成本。
`MusicLibraryEditor` 则是**确实漏了**安卓分支（见 `07` 第 3 节）。

⚠️ `useReducedMotion` 首帧恒 false，所以桌面开「减少动态效果」时 `lite` 会晚一帧才生效
（见 `01` 第 4 节）。**不要把它接到 framer-motion 的 `initial` 上。**

## 5. 安卓合成器踩坑清单

这些都**在桌面复现不到**，改动涉及 3D / filter / 弹层时必须逐条核对。

### 5.1 `preserve-3d` 逃出 stacking context（鬼影）
3D 上下文里的卡片会画到 z-index 更高的覆盖层上面 —— 透过不透明面板能看到卡片鬼影。
纯 CSS（不透明背景 / 提层 / 封层）压不住，**唯一可靠手段是让卡片不渲染**。

### 5.2 `opacity < 1` 会扁平化 3D（整面墙跳位）
`opacity` 是 CSS grouping property，按规范会把该元素的 `transform-style` 强制为 `flat`。
安卓上淡出那一瞬透视投影整体塌陷，用户看到的是「整面墙一起跳位」（打开淡出、
关闭淡入各塌一次）。**只能用 `visibility` 瞬切**，代价是没有淡出（被弹层入场掩盖，可接受）。

### 5.3 `visibility` 会被子级逆转
父层写 `hidden` 不够 —— rAF 每帧给卡片写的 `visible` 会把它翻回来。
隐藏职责必须落到**实际写样式的那一层**。

### 5.4 动画化的 `filter` 叠在 `backdrop-filter` 上会撕裂
安卓 Chrome 的 GPU 合成器会撕裂后备缓冲，表现为一瞬间的「碎屏 / 雪花噪点」闪光。
iOS Safari（WebKit + CoreAnimation / Metal）没有这个问题，所以 iPhone/iPad 保留完整磨砂。
安卓上的做法是：**实底背景 + 去掉动画里的 `filter: blur`**。

### 5.5 平台判定必须首帧就准（framer-motion 的坑）
`initial` 只在挂载那一帧读一次。首帧给错值 → 先按非安卓变体渲染 →
之后换成安卓变体时 framer-motion **会撒手不再管 `filter`** → blur 卡死 →
面板/列表在安卓上永久模糊。所以 `useIsAndroid` 用 `useState(detect)` 同步初始化，
**绝不用 `useState(false) + useEffect` 翻转**。
（SSR 安全的前提是所有消费方都 `ssr: false`，见 `01`。换到会服务端渲染的组件里要重新评估。）

### 5.6 安卓 App 的底边鬼影与「窗口缩小就不出现」
遮挡区宽度必须取整屏宽而非播放器宽 —— 详见 `02` 第 7 节的表格与解释。

### 5.7 合成层的「创建 / 销毁」本身就是撕裂触发点
framer-motion 只在动画进行中自动加 `will-change`，一头一尾的提层/落层正是安卓 WebView
撕裂闪屏的时机（本项目反复验证过）。**频繁进出动画的毛玻璃层要常驻 `will-change: transform`**，
别等框架加（`ShareDeck` 就是这么做的，见 `07` 第 2 节）。

### 5.8 大圆角 + 大阴影的元素别做缩放/透明度动画
安卓上会逐帧重光栅化并撕裂显存缓冲。`ShareDeck` 在安卓上把 `scale` 与 `opacity` 锁死为 1，
纵深只靠位移、倾斜和层级表达 —— 这套「换一种表达而不是关掉效果」的思路可以照搬。

## 6. 加新效果前的检查清单

1. 它需要 `filter` 吗？→ 若挂在卡片或卡片祖先上，**直接否决**（废掉 backdrop-filter）。
2. 它需要全屏模糊吗？→ 必须给 `lite` 一条跳过的分支。
3. 它会引入新的高频 state 吗？→ 走 getter 轮询或探针组件，不要塞进卡片订阅的 context。
4. 它在动画期间改 `opacity` 且祖先是 3D 层吗？→ 换 `visibility`。
5. 它是 framer-motion 且 variants 里有 `filter` 吗？→ 平台判定必须同步取值。
6. 改完在 `/music?perf` 上跑一遍，桌面 + `?force=mobile` 各记一组数字。
